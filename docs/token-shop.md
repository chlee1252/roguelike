# 고양이·배경과 토큰 상점

## 현재 구현

메인 화면의 **고양이 · 상점**에서 고양이, 배경 테마, 토큰 구매 탭을 엽니다. 기본 치즈냥과 달빛 골목은 무료입니다. 추가 고양이와 배경은 같은 토큰 잔액으로 해금하는 구조이며, 각각 선택을 저장합니다. 고양이는 기본 체력·이동 속도가 같고 시작 무기가 다릅니다(치즈냥: 생선뼈, 턱시도냥: 장난감 공, 삼색냥: 하악질, 눈송이냥: 털뭉치). 네 무기는 모두 무료 레벨 업 선택지에도 포함됩니다. 배경은 동일한 스테이지의 외형입니다. 적 배치·충돌·보스·난도는 바뀌지 않습니다.

| 분류 | 상품 | 토큰 |
|---|---|---:|
| 고양이 | 치즈냥 | 기본 제공 |
| 고양이 | 턱시도냥 | 80 |
| 고양이 | 삼색냥 | 140 |
| 고양이 | 눈송이냥 | 180 |
| 배경 | 달빛 골목 | 기본 제공 |
| 배경 | 벚꽃 산책길 | 100 |
| 배경 | 비 오는 네온 골목 | 140 |
| 배경 | 포근한 눈꽃 골목 | 180 |

벚꽃길은 꽃나무와 흩날리는 꽃잎, 네온 골목은 차가운 간판빛·빗줄기·웅덩이, 눈꽃 골목은 눈 쌓인 지붕·처마·작은 눈송이로 구분합니다. 장식은 고정 24개를 배경에 그려 전투 판정과 분리합니다.

유료 토큰은 최초 지급하거나 플레이 보상으로 주지 않습니다. 토큰 패키지는 `nightcat.tokens.100`, `nightcat.tokens.300`, `nightcat.tokens.700`으로 설계했습니다. 원화 가격은 아직 정하지 않았으며, 출시 시 각 스토어에서 조회한 현지화 가격을 표시해야 합니다.

**현재 일반 빌드에서는 현금 결제가 불가능합니다.** 토큰 구매 버튼에 ‘결제 준비 중’이 표시됩니다. 네이티브 결제 플러그인, 스토어 상품, 로그인과 운영 서버가 아직 연결되지 않았습니다. 로컬 버튼만으로 유료 잔액을 늘리지 않습니다. 실제 결제 성공·영수증 검증·소비 처리를 테스트했다는 의미가 아닙니다.

## 결제 없이 동작 확인하기

Godot 디버그 실행에서만 별도 테스트 상점을 엽니다.

```sh
cd /Users/marc/dev/roguelike
godot --path . -- --shop-preview
```

1. **고양이 · 상점 → 토큰 구매 → 가상 구매 · 무료 테스트**를 누릅니다.
2. 300 토큰을 받은 뒤 턱시도냥 80, 벚꽃길 100 토큰을 해금합니다.
3. 잔액 120 토큰과 선택 상태를 확인하고 산책을 시작합니다.
4. 같은 명령으로 재실행하면 선택·해금·잔액이 유지됩니다.

테스트 잔액은 `.preview-collection.cfg`, 일반 캐시는 `.collection.cfg`에 저장되며 서로 섞이지 않습니다. 릴리스 빌드는 명령 인자를 무시합니다. 테스트 지급 경로는 운영 결제에 사용하면 안 됩니다.

## 코드 구조

- `ui/cat_pixel.gd`: 새로 그린 32×32 고양이, 네 가지 무늬, 앉기/걷기 프레임. 큰 눈구멍·입·흰 주둥이를 없애고 작은 눈과 코, 넓은 얼굴로 정리했습니다. 사용자가 제공한 `docs/cat_pixel.png`와 [단순한 고양이 픽셀 참고](https://www.pinterest.com/pin/58124651435877068/)의 비율을 관찰했습니다. 참고 이미지는 게임에 포함하지 않았습니다.
- `game/alley_theme.gd`: 배경 팔레트와 장식. `field.gd`가 전투 배경에, `mission_art.gd`가 미리보기에 적용합니다.
- `game/cat_collection.gd`: 잔액·해금 목록의 로컬 캐시 및 선택 저장. 유료 토큰 원장이 아닙니다.
- `game/token_shop.gd`: 테스트 상점과 HTTPS 서버 클라이언트. 운영 해금 요청은 상품 종류·ID만 보내며 가격이나 잔액을 보내지 않습니다.
- `server/ledger.py`: SQLite 서버 원장. 검증된 구매 1회 지급, 계정별 소유권, 고양이/배경 공용 잔액, 원자적 차감. 중복 영수증과 중복 해금 요청은 재차 지급·차감하지 않습니다.
- `server/api.py`: WSGI API 팩토리. 실제 인증 함수와 영수증 검증기를 주입해야 합니다. 클라이언트가 보내는 계정 ID는 사용하지 않습니다.

## 운영 연결 계약과 남은 작업

앱의 HTTPS 클라이언트는 개발 환경에서 `NIGHTCAT_SHOP_URL`, `NIGHTCAT_SHOP_ACCESS_TOKEN`을 읽을 수 있습니다. 운영 모바일 앱에는 로그인에서 얻은 단기 사용자 세션을 전달하도록 연결해야 하며, 비밀 키나 공용 관리자 토큰을 앱에 넣으면 안 됩니다. 현재 자동 로그인·계정 생성·앱 시작 시 서버 동기화는 없습니다. 연결 시 상점의 ‘구매 내역 새로고침’을 사용합니다.

인증된 `POST /wallet`은 `{}`를, `POST /unlock`은 `{"kind":"cat","id":1}` 또는 `theme`를 받습니다. 성공 응답은 `{"tokens":120,"cats":[0,1],"themes":[0,1]}`입니다. 클라이언트는 이 응답을 캐시합니다. 통신 실패 후 같은 해금을 재시도해도 서버는 중복 차감하지 않습니다.

`POST /receipt`는 `{"proof": ...}`를 받는 서버 경계까지 구현되어 있습니다. **실제 스토어 검증기는 아직 없습니다.** `Ledger`에 주입하는 검증기는 클라이언트 필드를 그대로 신뢰하지 말고, Apple 서명 거래 또는 Google 구매 조회로 앱 ID·상품·계정 연결·수량·상태·환경·취소 여부를 확인해야 합니다. 실패/보류/취소 거래는 지급하지 않습니다. 테스트 검증기는 단위 테스트 파일 안에만 존재합니다.

출시에 필요한 작업은 다음과 같습니다.

1. App Store Connect / Play Console에 소모성 토큰 상품 3개 등록, 판매 가격·테스트 계정 구성.
2. Godot 4.7 호환 iOS/Android 네이티브 결제 플러그인 설치·빌드 및 거래 증빙 전달 구현. 상품 조회 가격·취소·보류·재시도 UI 연결. 현재 구매 버튼은 의도적으로 비활성 상태입니다.
3. 로그인/계정 복구, HTTPS 운영 API, 실제 영수증 검증기와 비밀 키 보관 구성. 설치 삭제·기기 변경 시 잔액/해금을 서버 계정에서 복구해야 합니다.
4. 원장 지급 확정 후 거래 finish/consume 및 실패 시 재시도 큐. 환불·취소 서버 알림에 따른 원장 조정과 감사 로그. 이 부분은 현재 원장 모듈에 포함되지 않습니다.
5. Apple Sandbox 및 Google 라이선스 테스트에서 실제 결제 흐름·중단/복구·중복·계정 변경 검증 후 버튼 활성화.

[Godot StoreKit 2 플러그인](https://github.com/godot-sdk-integrations/godot-storekit2)은 개발 중 API이며 현재 README의 구매 상태만으로 서버 유료 토큰을 지급할 수는 없습니다. [Google의 구매 검증 지침](https://developer.android.com/google/play/billing/security)에 맞춰 구매 증빙 검증과 서버 지급을 연결해야 합니다. 플러그인을 설치하는 것만으로 이 작업이 완료되지는 않습니다.
