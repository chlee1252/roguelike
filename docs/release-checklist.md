# 운영 출시 체크리스트 SSOT

최종 갱신: 2026-09-13 · 대상: iOS·Android 첫 운영 출시

현재는 핵심 전투·세 맵·영구 운동이 구현된 플레이테스트 단계다. 자동 검사 통과와 운영 출시 준비 완료는 구분한다. 이 문서는 출시까지 남은 작업의 범위·우선순위·진행 상태·완료 근거를 관리하는 단일 기준이다.

## 관리 규칙

- 관련 작업 시작 전에 이 문서를 읽고 해당 항목 ID를 확인한다. 새로운 출시 작업은 이 문서에 추가하고 ID를 유지한다.
- 기본 상태는 `[ ]` 미완료다. 진행 중·차단 상태는 해당 항목 뒤에 `진행 중: …` 또는 `차단: …`로 기록한다. 차단 시 필요한 조건과 다음 행동을 함께 남긴다.
- 구현과 해당 항목에 필요한 검증을 모두 마친 뒤에만 `[x]`로 변경한다. 완료일과 코드·테스트·검증 기록 링크를 같은 항목에 남긴다. 코드 작성만으로 실기기 검증이나 사람 플레이테스트를 완료 처리하지 않는다.
- 변경한 기능에 대응하는 항목은 같은 변경 묶음에서 갱신한다. 회귀가 발견되면 다시 `[ ]`로 열고 실패 근거를 기록한다.
- 출시 범위에서 제외한 항목은 삭제하거나 완료로 표시하지 않는다. `[ ]`를 유지하고 `해당 없음: 결정일·사유` 또는 `출시 후 이관: 결정일·사유`를 기록한다. 채택한 출시 범위에 근거가 있어야 한다.
- 별도 문서에 같은 체크리스트를 복제하지 않는다. 상세 설계·검증 결과는 관련 문서에 작성하고 여기에서 링크한다. 작업 목록과 상태가 충돌하면 이 문서를 기준으로 실제 코드·검증 근거를 확인해 정정한다.
- 갱신할 때 위의 최종 갱신일도 수정한다. 배포 체크 완료는 배포 실행이나 외부 계정 변경의 승인 자체를 뜻하지 않는다.

세계관·에셋·문구는 [스토리보드 SSOT](storyboard.md), 맵·재화·운동 규칙은 [레벨 설계](level-design.md), 실행 구조는 [게임플레이](gameplay.md), 검사 증거는 [검증 기록](game-validation.md)이 담당한다.

## 출시 범위와 순서

- [ ] REL-01 — 첫 출시 플랫폼과 지원 기기·OS 범위 확정. 완료 기준: 지원 범위와 테스트 기기 목록 기록.
- [ ] REL-02 — 유료 상점 포함 여부 확정. 완료 기준: 결제 포함 출시 또는 무료 선출시를 기록하고 아래 조건부 항목에 반영.
- [ ] REL-03 — 재설치·기기 변경 시 진행도 복구 범위 확정. 완료 기준: 로컬 전용 또는 클라우드 저장의 범위와 사용자 안내 결정. 유료 구매 내역 복구와 게임 진행도 복구를 구분.

착수 순서: SAVE-01 → SAVE-02·SAVE-03 → PLAY 항목과 DEVICE 항목. 결제를 포함한다면 PAY 항목과 운영 서버 준비를 병행한다. RELEASE 항목으로 출시 후보를 검증한 후 배포한다.

## 1. 저장·재화 보호 — 배포 전 필수

- [ ] SAVE-01 — 새 게임 시작 시 기존 판의 재료 보호. 현재 `game/run.gd`의 `start_run()`은 기존 산책 저장을 삭제한다. 완료 기준: 수집분 정산 후 새 판 시작 또는 손실을 명확히 알리는 종료 확인 흐름을 구현하고 회귀 테스트 추가.
- [ ] SAVE-02 — 자동 저장 실패 감지·안내·재시도. 완료 기준: 파일 쓰기·flush·교체 실패를 확인하고, 저장하지 못한 상태를 성공으로 표시하지 않으며 복구 후 정상 저장되는지 검사.
- [ ] SAVE-03 — 손상된 저장의 복구 경로. 완료 기준: 마지막 정상 백업과 복구 UI 제공, 손상 파일을 덮어쓰지 않고 진행·재료를 복구하는 테스트 추가. 현재는 잘못된 저장을 거부하는 수준.
- [ ] SAVE-04 — 설치본 업데이트 시 저장 유지. 완료 기준: 이전 버전 위에 출시 후보를 설치해 운동·재료·가구·해금·진행 중 산책과 미완료 정산을 확인하고 결과 기록.
- [ ] SAVE-05 — REL-03에 따른 진행도 복구 구현. 클라우드 지원 시 계정 연결·업로드·복원·충돌 해결·오프라인 재접속을 검증한다. 로컬 전용이면 삭제·기기 변경의 한계를 안내하고 클라우드 작업의 이관 사유를 기록한다.

관련 코드: [산책·화면](../game/run.gd), [영구 진행·정산](../game/night_progress.gd), [전투 스냅샷](../game/battle.gd). 기존 성장 회귀 검사: [training_test.gd](../tests/training_test.gd).

## 2. 실제 플레이와 성장 밸런스 — 배포 전 필수

- [ ] PLAY-01 — 첫 재료·첫 운동 도달 테스트. 완료 기준: 처음 하는 사람이 첫 2~3분에 재료를 발견하고 패배 후 운동을 구매하는지 관찰·기록하고 막히는 안내나 배치를 수정.
- [ ] PLAY-02 — 운동 0레벨의 첫 보스 검증. 완료 기준: 사람 플레이로 클리어 가능성과 초반 난도를 확인. 무적 봇 결과를 근거로 대체하지 않음.
- [ ] PLAY-03 — 세 맵 웨이브·보스 조정. 완료 기준: 사망 시점·원인·공략 시간을 기록하고 예고·지형·탄막을 합쳐 회피할 길이 없는 상황과 과도한 대기 구간 수정.
- [ ] PLAY-04 — 운동 비용·재료 획득량 조정. 완료 기준: 첫 강화와 중후반 강화에 필요한 판 수, 운동 전후 보스 도달률, 재도전 의사를 기록하고 반복 부담 점검.
- [ ] PLAY-05 — 결과 화면의 패배 원인 표시 보강. 현재 결과 화면은 마지막 위험 대신 수집량을 보여준다. 완료 기준: 수집 보상과 마지막 피격 원인을 함께 읽을 수 있고 플레이어가 패배 이유를 이해하는지 확인.
- [ ] PLAY-06 — XP·회복 음식·보관용 재료 구분 보완. 완료 기준: 신규 플레이어가 각 아이템의 용도와 종료 후 유지 여부를 설명할 수 있도록 문구·아이콘·획득 피드 검수.

상세 관찰 절차는 [플레이테스트 진행표](playtest-guide.md), 수치 기준은 [레벨 설계](level-design.md)를 사용한다.

## 3. 실기기 품질 — 배포 전 필수

- [ ] DEVICE-01 — 최신 출시 후보의 실제 iPhone·중저가 Android 장시간 플레이. 완료 기준: REL-01의 지원 기기에서 15분 이상 전투하고 빌드·기기·OS·결과 기록.
- [ ] DEVICE-02 — 최대 부하 성능 개선. 완료 기준: 적·탄막 최대 상황의 프레임 시간·메모리·발열·배터리 소모를 측정하고 지원 기기의 목표 기준을 충족. 데스크톱 시뮬레이션 시간과 구분.
- [ ] DEVICE-03 — 전화·알림·백그라운드·강제 종료 후 복원. 완료 기준: 전투·레벨 업 선택·재료 습득·정산 각각에서 중단 후 복원하고 중복 지급·손실 여부 확인.
- [ ] DEVICE-04 — 화면·입력 검수. 완료 기준: 노치·다양한 화면 비율·양쪽 가로 회전·작은 글씨·터치 영역을 실제 화면에서 확인하고 겹침·잘림·오입력 수정.
- [ ] DEVICE-05 — 사운드·햅틱 조정. 완료 기준: 휴대폰 스피커의 음악/효과음 균형, 장시간 피로도, 진동 강도와 끄기 설정을 실기기에서 확인.

이전 설치 성공만으로 최신 후보 검증을 완료 처리하지 않는다. [실기기 햅틱 안내](haptics.md), [기존 검증 기록](game-validation.md)을 참고한다.

## 4. 유료 상점 — 결제 포함 출시 시 필수

현재 일반 빌드의 실제 현금 결제는 미연결이다. REL-02에서 무료 선출시를 선택하면 PAY-01~PAY-06을 출시 후로 이관하고 PAY-07을 완료해야 한다. 결제 포함 출시라면 PAY-07에 해당 없음 사유를 기록한다.

- [ ] PAY-01 — 로그인·계정 복구·구매 내역 자동 동기화. 완료 기준: 앱 시작·재설치·기기 변경·계정 전환에서 잔액과 구매 소유권을 올바른 계정으로 복구.
- [ ] PAY-02 — 운영 결제 API 구성. 완료 기준: HTTPS·인증·서버 비밀 키 관리·원장 백업과 복구·장애 알림을 운영 환경에서 검증. 앱에 공용 관리자 토큰을 넣지 않음.
- [ ] PAY-03 — 네이티브 결제 연결. 완료 기준: 지원 플랫폼의 결제 플러그인과 스토어 상품 등록, 현지화 가격 조회, 구매·취소·보류 UI 연결.
- [ ] PAY-04 — 영수증 검증과 거래 완료. 완료 기준: 서버 검증 → 중복 없는 토큰 지급 → 스토어 거래 완료/소비 처리를 연결하고 중단·재시도 큐 검증.
- [ ] PAY-05 — 환불·취소 반영. 완료 기준: 서버 알림·원장 조정·감사 로그를 구현하고 이미 사용한 토큰의 환불 처리 정책 적용.
- [ ] PAY-06 — 실제 스토어 테스트. 완료 기준: 테스트 환경에서 성공·취소·보류·중복·통신 단절·재실행·환불·기기 변경을 검증한 뒤 운영 결제 활성화.
- [ ] PAY-07 — 무료 선출시용 상점 정리. 완료 기준: 구매 불가능한 화면을 정리하고 잠긴 고양이·배경의 제공 방식을 확정해, 구매 가능한 것처럼 안내하지 않음.

상세 연결 계약은 [상점 문서](token-shop.md)에 둔다. 결제 구현 시 [Google 공식 결제 지침](https://developer.android.com/google/play/billing/integrate)과 대상 스토어의 최신 요구사항을 다시 확인한다.

## 5. 배포·운영 준비 — 배포 전 필수

- [ ] RELEASE-01 — 운영 앱 ID·버전·빌드 번호와 릴리스 서명. 완료 기준: 실제 배포 계정 설정으로 서명한 설치 가능한 릴리스 산출물 생성. 서명 비밀은 저장소에서 제외.
- [ ] RELEASE-02 — CI 연결. 완료 기준: 게임·서버 테스트와 릴리스 빌드 검사가 자동 실행되고 실패 시 출시 후보로 승격하지 않음.
- [ ] RELEASE-03 — 운영 진단·문의 경로. 완료 기준: 크래시·저장 실패·결제 실패를 확인할 수단, 빌드 식별 정보, 사용자 문의 경로와 대응 담당/절차 마련. 수집 데이터 범위를 명시.
- [ ] RELEASE-04 — 개인정보·라이선스 정리. 완료 기준: 실제 수집·전송 동작과 개인정보 처리방침·스토어 고지를 맞추고 폰트·이미지·음원 등 배포 에셋 사용 근거 기록.
- [ ] RELEASE-05 — 계정 삭제. 계정 생성을 제공할 때 적용한다. 완료 기준: 앱 내 삭제 진입·서버 처리·연결 데이터와 세션 처리 검증. 계정 기능이 없으면 해당 없음 근거 기록.
- [ ] RELEASE-06 — 스토어 제출 자료. 완료 기준: 실제 플레이 기반 소개·스크린샷·연령등급 정보·심사 안내 준비. 로그인이 필요하면 심사용 접근 수단과 서버 가동 확인.
- [ ] RELEASE-07 — 출시 후보 검증. 완료 기준: TestFlight·Play 내부 테스트 등 선택 플랫폼의 배포 경로에서 설치·업데이트·게임·저장·적용되는 결제 흐름을 확인하고 차단 이슈 해소.
- [ ] RELEASE-08 — 단계적 배포와 장애 대응. 완료 기준: 배포 범위·관찰 지표·중단 기준·긴급 수정 절차를 기록. 서버 변경이 있다면 되돌리기와 데이터 복구 절차도 검증.

제출 시 [Apple 심사 지침](https://developer.apple.com/app-store/review/guidelines/) 등 대상 스토어의 최신 정책을 확인한다. 이 문서는 정책 원문의 대체물이 아니다.

## 6. 출시 후로 미룰 수 있는 콘텐츠

아래 항목은 기본 출시 차단 조건에 포함하지 않는다. 첫 출시 범위로 채택하면 해당 필수 단계로 옮기고 완료 기준을 추가한다.

- [ ] LATER-01 — 스토리보드의 추가 컷신·전용 환경음.
- [ ] LATER-02 — 고양이별 표정·운동·패배·재회 애니메이션 확장.
- [ ] LATER-03 — 추가 맵·무기·보스·고양이.
- [ ] LATER-04 — 일일 도전·도전 과제·추가 수집 요소.

## 출시 준비 완료 판정

REL 범위가 정해지고 SAVE·PLAY·DEVICE·RELEASE의 적용 항목, REL-02에 따라 적용되는 PAY 항목이 모두 완료되어야 한다. 조건부 제외는 결정 근거가 있어야 하며 미해결 차단 이슈가 없어야 한다. 검증 기록에는 출시 후보의 커밋 또는 빌드 식별자를 남긴다. 기존 자동 테스트 결과만으로 위 항목을 일괄 완료 처리하지 않는다.
