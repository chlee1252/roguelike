# 실기기 햅틱

설정에서 **햅틱(진동)**을 켜고 **진동 테스트**를 누르면 피격과 같은 짧은 진동이 난다. 효과음과 별도로 켜고 끌 수 있으며 설정은 앱을 다시 실행해도 유지된다. PC에서는 테스트 버튼이 ‘실기기 전용’으로 비활성화된다. 시뮬레이터 화면으로 진동의 감촉을 확인할 수는 없다.

| 상황 | 길이 | 요청 강도 |
|---|---:|---:|
| 레벨 업 선택 완료 | 35ms | 0.30 |
| 고양이 피격 | 65ms | 0.55 |
| 무기 진화 | 110ms | 0.70 |
| 보스 처치·승리 | 160ms | 0.85 |

일반 공격·경험치 획득·개별 적 처치에는 진동을 넣지 않는다. 최소 간격은 250ms이며, 진화·승리처럼 우선순위가 높은 이벤트만 직전의 약한 진동을 덮을 수 있다. 한 프레임에 여러 전투 이벤트가 발생하면 가장 중요한 하나만 재생한다. 백그라운드 요청은 버리고 복귀 후 몰아서 재생하지 않는다. 예약 진동은 없으며 이미 시작한 짧은 펄스는 지정 시간에 끝난다.

`CombatHaptics`는 [Godot Input.vibrate_handheld](https://docs.godotengine.org/en/stable/classes/class_input.html#class-input-method-vibrate-handheld)를 사용한다. Android 내보내기 설정에 `permissions/vibrate=true`를 추가했다. iOS도 같은 API를 사용한다. 실제 강도와 지원 여부는 기기 하드웨어·OS 설정에 따라 달라진다.

## 실기기에서 확인하기

1. Android는 USB 디버깅을 켜고 연결한 뒤 아래 명령으로 설치한다. iPhone은 README의 iOS 프로젝트 내보내기 후 Xcode에서 개발 팀과 서명을 설정하고 연결한 iPhone을 실행 대상으로 선택한다.
2. **설정 → 햅틱(진동) 켜짐 → 진동 테스트**로 모터 동작을 확인한다.
3. 효과음만 끄고 테스트해도 진동이 나는지 확인한다. 햅틱을 끄면 테스트 버튼이 비활성화되고 전투 중에도 진동이 없어야 한다.
4. 실제 플레이에서 피격·레벨 업·진화·보스 처치를 확인한다. 앱을 홈으로 보냈다가 복귀했을 때 지난 이벤트가 뒤늦게 울리지 않아야 한다.
5. 앱을 재실행해 끄기 설정이 유지되는지 확인한다. 짧은 피격 진동이 거슬리거나 승리 진동이 너무 강한지는 실기기 플레이로 조정한다.

```sh
godot --headless --path . --export-debug Android build/LastCommando.apk
adb devices
adb install -r build/LastCommando.apk
```

## 검증 범위

`tests/haptics_test.gd`는 실제 모터 대신 호출 기록을 받아 강도·길이·이벤트 우선순위·빈도 제한·음소거와의 독립성·설정 저장·앱 포커스 전환을 검사한다. Android APK의 실제 manifest에 VIBRATE 권한이 포함되는지도 빌드 후 확인한다.

2026-09-12 확인 당시 연결 가능한 Android 휴대폰이 없었고, 등록된 iPhone/iPad는 `unavailable` 상태였다. 따라서 실제 모터 진동이나 iOS 실기기 실행을 확인했다고 보지 않는다.
